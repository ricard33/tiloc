# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is the React/TypeScript frontend for Tiloc (a vacation rental management SaaS: bookings, lodgings,
payments, contracts, calendar sync, etc.). It is built with Vite, was originally bootstrapped with
Create React App (some CRA-era conventions remain), and is served behind a Django backend — in dev, Vite
proxies `/api`, `/stats` and `/loggly` to `http://127.0.0.1:8000`.

## Commands

Package manager is **yarn** (yarn.lock is the source of truth).

- `yarn start` — run dev server on port 3000 (Vite)
- `yarn build` — type-check (`tsc`) then production build to `build/`
- `yarn compile` — type-check only, no emit (`tsc`)
- `yarn lint` — ESLint over `src`
- `yarn test` — run Vitest (watch mode by default)
- `yarn test run` — run Vitest once, non-watch (CI-style)
- `yarn test run <path or name pattern>` — run a single test file or filter by name
- `yarn coverage` — Vitest run with coverage
- `yarn extract` — extract i18next translation keys from source into locale JSON via `config/i18next-parser.config.cjs`

Tests use Vitest with `jsdom` environment and `@testing-library/react`; setup file is `src/setupTests.ts`.
Test files are colocated with the code they test (`*.test.ts`/`*.test.tsx`/`*.test.js`), not in a separate
`__tests__` tree.

### Private dependency

`@ti-gecko/tiloc-ckeditor5` is a private package sourced locally from `./ckeditor5` (see `package.json`
`"file:./ckeditor5"` dependency and `README.md`). If it's missing/out of date, it needs to be linked from
the sibling `tiloc-ckeditor` repo via `yarn link`.

## Architecture

### State management: Redux Toolkit + RTK Query + redux-saga

- `src/store.ts` — configures the store. Root reducer manually clears all state except `appInfo` on
  `LOGOUT_SUCCESSFUL` (see the custom `reducer` function, not a plain reducer map). RTK Query's `api`
  reducer lives alongside three hand-written slices under `src/reducers`: `alert`, `auth`, `appInfo`.
- `src/services/api.ts` — the single RTK Query API slice (`createApi`) for **all** backend communication.
  It does not use `fetchBaseQuery`; instead `axiosBaseQuery()` wraps axios (needed for FormData/file-upload
  support and custom multipart handling — see the `data` → `FormData` conversion logic for `PUT`/`PATCH`/`POST`).
  - CRUD endpoints for most models are generated by the `makeApi<T>(url, modelName, convertFromApi?, convertToApi?)`
    factory (→ `.list`/`.pages`/`.get`/`.create`/`.update`/`.delete`), rather than hand-written per model.
    When adding a new model's CRUD endpoints, prefer extending this factory pattern over writing bespoke
    endpoints. One-off endpoints (login, contract generation, move up/down, etc.) are written directly in the
    `endpoints` builder.
  - Every generated hook is re-exported by name at the bottom of the file (`useListXxxQuery`,
    `useCreateXxxMutation`, ...) — components consume these hooks, never axios/the API slice directly.
  - Tag-based cache invalidation (`tagTypes` + `providesTags`/`invalidatesTags`) drives refetching;
    `invalidatesDependentTags()` hardcodes cross-model invalidation (e.g. a `Comment` change invalidates its
    parent `Booking`).
- `src/sagas.ts` — a small root saga only responsible for auth token side effects (persisting/removing the
  JWT in `localStorage` on login/logout/auth-error actions). Business data fetching goes through RTK Query,
  not sagas.
- API request/response shapes frequently differ from the frontend's TypeScript models (dates as ISO strings
  vs `Date`, decimal strings vs `number`, nested vs flattened ids). `src/types/models-convertion.ts` holds
  the `api2Xxx` / `xxx2Api` converter pairs used as `convertFromApi`/`convertToApi` in the `makeApi` calls
  and in ad-hoc endpoints' `transformResponse`. When adding a model with non-trivial field types, add
  converters here rather than doing conversion in components.

### Auth & routing

- `src/Routes.tsx` defines all routes. Public routes render inside `MinimalLayout`; authenticated routes are
  wrapped in `<Route element={<RequireAuth />}>` and render inside `MainLayout` (`src/layouts`).
  `RequireAuth` (`src/components/RequireAuth.tsx`) redirects to `/login` when unauthenticated, and to
  `/setup` (account wizard) when the user's account isn't yet initialized.
  Large/rarely-hit views (e.g. `Planning`, `Guests/GuestsList`) are `React.lazy`-loaded.
- `App.tsx` is the root: loads `appInfo` (`/api/info/`) on an interval, fetches the current user via
  `useCurrentUserQuery`, and gates rendering the app behind `appInfo.loaded` (shows `LoadingInProgress`
  until then). It also surfaces subscription/trial-expiry alerts based on `currentUser.account`.

### Views & components

- `src/views/<Feature>/` holds one directory per top-level feature (Lodging, BookingList, Payment, Settings,
  Subscription, Wizards, ...), typically a `XxxList.tsx` + `XxxPage.tsx`/`XxxForm.tsx` pair following the
  list/detail-form convention seen in Lodging, Services, Users, CalendarSync, BookingChannel.
- `src/components/` holds shared, cross-feature UI (dialogs, tooltips, grid toolbar, payment widgets, the
  CKEditor wrapper, etc.). `src/layouts/` holds the two page shells (Main with sidebar/topbar, Minimal).
- MUI (`@mui/material`, `@mui/x-data-grid`, `@mui/x-date-pickers`) is the component library; theme lives in
  `src/theme/` (`index.ts`, `palette.ts`, `typography.ts`). Forms generally use `react-hook-form` /
  `react-hook-form-mui` with `validate.js` (custom validators registered in `App.tsx` from
  `src/common/validators.ts`).

### Naming convention (from README)

- Standard files: lower-case, `-`-separated
- Component files: same name as the component, in CamelCase

### i18n

- `src/i18n.ts` configures i18next with `fr` as default language, `en` fallback, single `common` namespace,
  and `keySeparator: false` (translation keys are the literal source strings, not dotted paths). Locale JSON
  lives in `src/locales/{en,fr}/common.json`. Run `yarn extract` to pull new `t()` calls into those files.

### Misc

- `src/common/` is a large grab-bag of framework-agnostic utilities (date/timezone handling, pricing,
  strings, colors, avatars, subscription plan logic, custom hooks like `useInterval`/`useDebounceEffets`).
  Check here before adding a new utility — there's likely something close already.
- Logging goes through `src/common/logger.js` (Loggly), gated by `VITE_LOGGLY_ACTIVE`/`VITE_LOGGLY_TAG`/
  `VITE_LOGGLY_CUSTOMER_TOKEN` env vars.
- Vite build manually chunks vendor bundles (`react`/`router`/`react-dom`, `chart.js`, `date-fns`, `mui`) —
  see `vite.config.ts` `rollupOptions.output.manualChunks`.
- Build output goes to `build/` with a Vite manifest (`vite-manifest.json`) for the Django backend to
  reference hashed asset filenames; base path is `/static/` in production.
